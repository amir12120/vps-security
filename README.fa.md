# vps-security 🛡️

**[English](README.md) | فارسی**

**ابزار ایمن‌سازی سرورهای اوبونتو/دبیان — یک CLI گرافیکی و تعاملی.**

`vpssec` با منوی گرافیکی (کلیدهای جهت‌دار + ایموجی) شما را قدم‌به‌قدم برای ایمن‌سازی یک سرور تازه همراهی می‌کند:

1. **به‌روزرسانی سیستم** — اجرای `apt update && apt upgrade -y`
2. **تغییر پورت SSH** — انتقال SSH از پورت ۲۲ به پورت دلخواه شما (با پشتیبان‌گیری خودکار و بازگشت به عقب در صورت خرابی)
3. **فایروال (ufw)** — نصب ufw، باز کردن **فقط** پورت‌هایی که تأیید می‌کنید و فعال‌سازی فایروال. لیست پورت‌ها را **یک‌جا و با کاما** وارد می‌کنید (`444,2086,2098,2689`) و همه باز می‌شوند. اگر **هیچ پورتی مشخص نکنید**، فایروال **غیرفعال** می‌ماند و سرور روی همه پورت‌ها باز می‌شود
4. **مانیتور پورت‌های غریبه** — هر ۳۰ دقیقه اتصال‌های فعال اسکن می‌شوند و هر پورتی که خارج از لیست مجاز شما در حال انتقال داده باشد **گزارش می‌شود** — همراه با IP مهاجم، کشور آن و شماره پورت. مسدودسازی فقط بعد از **تأیید شما** انجام می‌شود
5. **سپر بات و اسکنر** — محدودیت نرخ اتصال برای هر IP، حذف بسته‌های اسکن با فلگ‌های TCP (NULL / SYN+FIN / SYN+RST / ALL) و **تشخیص** سیل SYN: IP مهاجم برای تصمیم شما در صف قرار می‌گیرد و بدون اطلاع شما بن نمی‌شود
6. **گردش کار تأیید (Approval)** — هشدارهای در انتظار در هر ورود SSH، در عنوان منو و در داشبورد دیده می‌شوند؛ دستور `sudo vpssec alerts` یکی‌یکی می‌پرسد: «IP فلان از کشور فلان دارد روی پورت فلان فعالیت مشکوک می‌کند؛ بنش کنم؟». پاسخ **y** → بن به مدت **۲۴ ساعت**، و هر بن در هر لحظه قابل لغو است تا اشتباه‌ها جبران‌پذیر بمانند
7. **نگهداری خودکار (Maintenance)** — هر ۲ روز یک‌بار رم-کش پاک می‌شود (`drop_caches`)، لاگ‌های چرخشی حذف، لاگ‌های فعال معمول کوتاه و ژورنال systemd با سقف حجم **و** عمر خلاکس می‌شود. پاک‌کردن swap به‌صورت پیش‌فرض **خاموش** است؛ از منوی Maintenance یا با `MAINT_CLEAR_SWAP=1` در `/etc/vps-security/maintain.conf` فعال کنید. لاگ‌های خود vps-security و همه زیرپوشه‌های `/var/log` هرگز دست‌نخورده می‌مانند و با `MAINT_EXCLUDE` یا منو می‌توانید فایل‌های بیشتری را مستثنا کنید
8. **فیلتر جغرافیایی (GeoIP)** — اجازه دسترسی به **هر تعداد کشور** که می‌خواهید (مثلاً فقط ایران و آلمان) و مسدود کردن بقیه کشورها

## نصب سریع (یک خط)

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/amir12120/vps-security/main/install.sh)
```

نصاب، مخزن را در `/opt/vps-security` کلون می‌کند، دستور `vpssec` را نصب و راه‌اندازی تعاملی را شروع می‌کند. **با پایان یافتن مراحل، منوی `vpssec` خودکار باز می‌شود** — همان منویی که هر وقت بخواهید با `sudo vpssec` باز می‌کنید.

| دستور | توضیح |
|---|---|
| `sudo vpssec install` | راه‌اندازی کامل تعاملی |
| `sudo vpssec status` | داشبورد: فایروال، SSH، مانیتور و شمارنده‌ها |
| `sudo vpssec ports` | افزودن / حذف / مشاهده پورت‌های مجاز |
| `sudo vpssec port` | تغییر پورت SSH |
| `sudo vpssec scan` | اجرای فوری اسکن پورت‌های غریبه (فقط گزارش می‌دهد، سپس پیشنهاد بررسی می‌کند) |
| `sudo vpssec alerts` | **بررسی هشدارهای در انتظار:** y = بن ۲۴ ساعته، n = رد کردن، s = بعداً، a = تأیید همه |
| `sudo vpssec alerts list` | نمایش صف هشدارها بدون تصمیم‌گیری |
| `sudo vpssec alerts approve <n>` / `dismiss <n>` | اقدام روی یک هشدار از اسکریپت |
| `sudo vpssec blocked` | مشاهده پورت‌های مسدود شده + زمان باقی‌مانده تا رفع مسدودی |
| `sudo vpssec unblock [port]` | آزادسازی فوری یک پورت مسدود |
| `sudo vpssec update` | به‌روزرسانی vps-security از گیت‌هاب |
| `sudo vpssec maint run` | اجرای فوری پاک‌سازی رم-کش و لاگ‌ها |
| `sudo vpssec maint status` | وضعیت تایمر نگهداری و آخرین اجراها |
| `sudo vpssec maint` | منوی نگهداری: اجرای فوری، کلید swap، سقف ژورنال، لیست مستثناها |
| `sudo vpssec shield status` | وضعیت سپر بات و IPهای بن‌شده |
| `sudo vpssec geo list` | تنظیمات فیلتر جغرافیایی |
| `sudo vpssec mirror` | **بهترین میرور و DNS ایرانی:** سرعت همه میرورهای گیتهاب، همه ریزالورهای ایرانی و همه میرورهای apt را از روی سرور شما می‌سنجد و سریع‌ترین هرکدام را سراسری نصب می‌کند — معیار: سرعت واقعی دسترسی به گیتهاب و apt |
| `sudo vpssec logs [n]` | نمایش لاگ مانیتور |
| `sudo vpssec uninstall` | **پاک‌سازی کامل:** حذف همه‌چیز، برگرداندن SSH به پورت ۲۲، reset و غیرفعال‌سازی ufw (با حفظ دسترسی SSH) |

## تشخیص ← اطلاع‌رسانی ← تأیید (هیچ‌چیز بدون اجازه شما بن نمی‌شود)

یک سرویس پرمشغله، ایجنت مانیتورینگ، سرور بکاپ یا همتای تانل از بیرون **دقیقاً** شبیه حمله به‌نظر می‌رسند و بن خودکار اشتباه روی سرور زنده خیلی سخت دیده می‌شود. پس vps-security دیگر حدس نمی‌زند: **تشخیص می‌دهد، به شما می‌گوید و منتظر می‌ماند**.

**۱. تشخیص.** هر ۳۰ دقیقه (و در صورت نیاز با `vpssec scan`) مانیتور دنبال پورت‌هایی می‌گردد که خارج از لیست مجاز شما ترافیک دارند و سپر دنبال IPهایی می‌گردد که سیل اتصال باز می‌کنند. هر دو فقط یک *هشدار* ثبت می‌کنند — نه قانون فایروال.

**۲. اطلاع‌رسانی.** در سه جا، تا از چشم شما دور نماند:

- **در هر ورود SSH** — فایل `/etc/update-motd.d/99-vps-security-alerts` تعداد رویدادهای منتظر و سه مورد اول را نشان می‌دهد
- **در عنوان منو** — `🚨 Pending alerts (2) — review & approve bans`
- **در `vpssec status`** — `Pending alerts : 2 suspicious event(s) — nothing blocked yet`

**۳. تأیید.** دستور `sudo vpssec alerts` صف را یکی‌یکی جلو می‌برد و برای هر رویداد فقط یک سؤال می‌پرسد:

```
  🚨 IP 203.0.113.5 (Netherlands) hitting port 22 — 45 new connections to port 22 in 30s (2m ago)
     Ban IP 203.0.113.5 for 24h?  [y = yes · n = no, dismiss · s = skip · a = approve all · q = stop]

  🚨 Port 3389 — rogue tcp service carrying traffic, not in your allow-list (just now)
     Block port 3389 for 24h?  [y = yes · n = no, dismiss · s = skip · a = approve all · q = stop]
```

- **y** → بن/مسدودسازی به مدت **۲۴ ساعت** روی ufw اعمال می‌شود
- **n** → رد می‌شود و فایروال دست نمی‌خورد (و به‌عنوان بررسی‌شده ثبت می‌شود)
- **s** → برای بعد در صف می‌ماند، **a** → تأیید همه، **q** → توقف

کشور نمایش‌داده‌شده به‌صورت آفلاین از لیست‌های CIDR کشوری که قابلیت GeoIP قبلاً دانلود کرده (یا `geoiplookup` در صورت نصب) استخراج می‌شود — هیچ درخواستی برای این کار از سرور خارج نمی‌شود.

**۴. انقضا یا لغو.** هیچ‌چیز دائمی نیست: تایمرهای مانیتور و سپر بن‌های منقضی را خودکار برمی‌دارند و شما هم می‌توانید فوری آزاد کنید — `sudo vpssec unblock <port>`، `sudo vpssec shield unban <ip>`، یا از منو: **🔓 Unblock a port** و **🛡️ Shield → Unban an IP**.

**چه چیزهایی حتی در صف هم قرار نمی‌گیرند:** پورت‌های مجاز، پورت‌های تانل اعلام‌شده، پورت SSH، پورت API گارد، پورت‌هایی که خودتان در ufw باز کرده‌اید، سرویس‌های فقط-loopback، آدرس‌های خصوصی/CGNAT و IPهای لیست *never block* (GeoIP bypass). موارد رد‌شده در `/var/lib/vps-security/alerts.log` ثبت می‌شوند.

**رفتار کاملاً خودکار قبلی را می‌خواهید؟** با یک تنظیم در دسترس است:

```bash
MONITOR_MODE=auto   # /etc/vps-security/monitor.conf — مسدودسازی فوری پورت غریبه
SHIELD_MODE=auto    # /etc/vps-security/botshield.conf — بن فوری IP مهاجم
```

## بهترین میرور و DNS ایرانی

روی سرورهای ایران، گیتهاب معمولاً کند یا غیرقابل‌دسترس است. گزینه **🏁 بهترین میرور و DNS ایرانی** در منو (یا دستور `vpssec mirror`) این مشکل را با اندازه‌گیری واقعی — نه حدس — حل می‌کند:

۱. **میرورهای گیتهاب** — همه میرورهای ایرانی گیتهاب (`gitclone.ir`، `github.iranserver.com`، `gitdl.theazizi.ir`) به‌علاوه مسیر مستقیم با دریافت واقعی HTTPS از پروتکل git زمان‌گیری می‌شوند. میرور برنده به‌صورت **سراسری** با `git config --system url.<mirror>.insteadOf https://github.com/` نصب می‌شود، تا همه دستورات `git clone/pull/fetch` — از جمله `vpssec update` — خودکار از میرور رد شوند.
۲. **DNS** — از فهرستی گسترده از ریزالورهای ایرانی برای `github.com` کوئری گرفته می‌شود و سریع‌ترین پاسخ‌دهنده روی سرور تنظیم می‌شود (drop-in مربوط به systemd-resolved یا در غیر این صورت `/etc/resolv.conf` با تهیه نسخه پشتیبان). این فهرست شامل سرویس‌های شناخته‌شده (شکن، ۴۰۳، رادار، بگذر، الکترو، پیشگامان، پناهگاه) به‌علاوه **حدود ۲۰ ریزالور ISP/مخابراتی** است که فقط از داخل ایران در دسترس‌اند؛ موارد تکراری حذف می‌شوند و ریزالورهای بدون نام تجاری با آدرس IP نمایش داده می‌شوند. هیچ چیزی بدون پاسخ واقعی نصب نمی‌شود.
۳. **میرورهای apt** — فایل `dists/<codename>/InRelease` از هر میرور اوبونتو (ایرانی‌ها و سپس چند گزینه خارجی) دانلود و سرعتش اندازه‌گیری می‌شود و سریع‌ترین در `sources.list` یا فایل deb822 یعنی `ubuntu.sources` نوشته می‌شود. ابتدا یک نسخه پشتیبان گرفته می‌شود، با `apt-get update` سالم بودن میرور اثبات می‌شود و **میروری که خطا بدهد خودکار برگردانده می‌شود** — پس apt هرگز خراب نمی‌ماند.

| دستور | کار |
|---|---|
| `sudo vpssec mirror best` | تست میرورهای گیتهاب و DNS و نصب سریع‌ترین‌های هرکدام |
| `sudo vpssec mirror apt` | تست میرورهای apt و تغییر به سریع‌ترین |
| `sudo vpssec mirror test` / `apt-test` | فقط نمایش جدول سرعت، بدون هیچ تغییری |
| `sudo vpssec mirror status` | نمایش وضعیت فعلی |
| `sudo vpssec mirror reset` | بازگرداندن همه چیز: حذف `insteadOf`، بازگرداندن DNS قبلی **و** تنظیمات پیش‌فرض apt |

نسخه پشتیبان اولیه (pristine) جدا از عکس‌های لحظه‌ای هر اجرا نگه‌داری می‌شود، پس `reset` حتی بعد از چند بار تغییر، تنظیمات پیش‌فرض توزیع را برمی‌گرداند.

## عملکرد مانیتور پورت‌های غریبه

- یک تایمر systemd اسکنر را **هر ۳۰ دقیقه** اجرا می‌کند (`OnBootSec=2min` و سپس `OnUnitActiveSec=30min`).
- اسکنر سوکت‌های زنده را از `ss -tunap` می‌خواند و فقط **سرویس‌های Bind شده روی آدرس عمومی** را در نظر می‌گیرد: پورت‌های TCP دارای سوکت `LISTEN` که واقعاً در حال سرویس‌دهی هستند، و پورت‌های UDP که خارج از محدوده‌ی پورت‌های موقت (ephemeral) Bind شده‌اند. سوکت‌های خروجی — همان پورت‌هایی که تانل، فراخوانی API پنل و آپدیت‌ها استفاده می‌کنند — هرگز کاندید مسدودسازی نمی‌شوند.
- هر پورت از این‌ها که در `/etc/vps-security/allowed-ports.list` نباشد، به‌عنوان پورت تانل اعلام نشده باشد و از قبل در ufw باز نباشد، به‌عنوان یک **هشدار در انتظار تأیید** در `/var/lib/vps-security/pending-alerts.list` ثبت و به شما گزارش می‌شود. **هنوز هیچ‌چیز مسدود نشده است.**
- با تأیید شماست که `ufw deny <port>/{tcp,udp}` اجرا می‌شود — به مدت **۸۶۴۰۰ ثانیه (۲۴ ساعت)** که با `BLOCK_SECONDS` در `/etc/vps-security/monitor.conf` قابل تنظیم است.
- پس از پایان این بازه، اسکن بعدی قانون را حذف و رویداد `UNBLOCK` را ثبت می‌کند.
- خود پورت SSH و پورت‌های خود مانیتور **هرگز** مسدود نمی‌شوند — حتی اگر در لیست مجاز نباشند.
- همه اقدامات در `/var/lib/vps-security/port-blocks.log` و `/var/lib/vps-security/monitor.log` ثبت می‌شوند.

> **نکته:** اسکنر فقط پورت‌های دارای اتصال زنده را می‌بیند. پورتی که فقط *گوش می‌دهد* (LISTEN) بدون انتقال داده علامت‌گذاری نمی‌شود — این باعث می‌شود ابزار با سرویس‌هایی که به‌طور قانونی گوش می‌دهند (پروکسی‌های docker، سوکت‌های پنل و…) تداخل نداشته باشد.

مشاهده پورت‌های مسدود (با شمارش معکوس زنده) از منوی **⛔ View blocked ports** یا دستور `vpssec blocked` و آزادسازی زودتر از موعد از منوی **🔓 Unblock a port** یا `vpssec unblock <port>` انجام می‌شود.

## تانل‌ها، ریورس‌پروکسی‌ها و سرورهای VPN

این سرورها معمولاً یک تانل روی خود دارند، پس هیچ بخشی از این برنامه نباید با تانل بجنگد. vps-security حول همین اصل ساخته شده است:

- **اتصال‌های خروجی هرگز دست نمی‌خورند.** تانلی که به سرور خارج وصل می‌شود، فراخوانی API پنل، `git fetch` — همه از پورت‌های موقت (ephemeral) استفاده می‌کنند و مانیتور کاملاً نادیده‌شان می‌گیرد. (نسخه‌های قدیمی همان پورت‌های مبدأ را بلاک می‌کردند و باعث اختلال تانل و پر شدن ufw از قوانین زائد می‌شدند.)
- **پورت‌های تانل را اعلام کنید** — `sudo vpssec tunnels add 8443,51820` یا **🔌 Ports → 🚇 Tunnel ports**. پورت اعلام‌شده در فایروال باز می‌شود، **هرگز** توسط مانیتور بلاک نمی‌شود و **هرگز** توسط سپر محدود (rate-limit) نمی‌شود.
- **سپر سرعت تانل را کم نمی‌کند.** قانون `ufw limit` در صورت بیش از ۶ اتصال جدید در ۳۰ ثانیه یک IP را دراب می‌کند و پورت تانل پرترافیک دقیقاً همین الگو را دارد — پورت‌های تانل از `ufw limit` و از اسکن auto-ban کنار گذاشته می‌شوند.
- **هیچ IP معتبری کورکورانه بن نمی‌شود.** سپر از بن کردن loopback، آدرس‌های خصوصی/CGNAT/link-local و هر IP در لیست *never block* (GeoIP bypass) خودداری می‌کند — کافی است IP همتای تانل را آنجا اضافه کنید: `vpssec geo bypass <ip>`.
- **سرویس‌های loopback و resolver دی‌ان‌اس** هرگز علامت‌گذاری نمی‌شوند و فیلتر جغرافیایی هرگز به ترافیک loopback دست نمی‌زند.
- **فیلتر کشوری فقط اتصال‌های NEW ورودی را دراب می‌کند** (`--ctstate NEW به همراه ! -i lo`). پاسخ اتصال‌هایی که *خود سرور* آغاز کرده جریان دارد، پس فعال کردن GeoIP نمی‌تواند تانل خروجی را قطع کند — حتی اگر سرور خارج در کشور غیرمجاز باشد.
- **نصب مجدد قوانین شما را حفظ می‌کند.** نصاب قبل از reset کردن ufw، قوانین `ALLOW` موجود را می‌خواند و دوباره اعمال می‌کند؛ پورت تانل یا پنلی که قبلاً باز کرده‌اید از بین نمی‌رود.
- **همه چیز را نشان می‌دهد.** مرحله نصب پورت‌هایی که همین حالا گوش می‌دهند را چاپ می‌کند و می‌پرسد کدام‌ها تانل هستند؛ `vpssec status` هم پورت‌های تانل اعلام‌شده را نشان می‌دهد.

```bash
sudo vpssec tunnels add 8443      # اعلام (و باز کردن در ufw)
sudo vpssec tunnels list          # نمایش پورت‌های محافظت‌شده
sudo vpssec tunnels remove 8443   # پایان محافظت
```

## جزئیات نگهداری

تایمر نگهداری هر ۲ روز اجرا می‌شود (با تا ۱۵ دقیقه پراکندگی تصادفی در زمان شروع تا همه سرورها همزمان پاک‌سازی نکنند).

| تنظیم (`/etc/vps-security/maintain.conf`) | پیش‌فرض | کاربرد |
|---|---|---|
| `MAINT_CLEAR_SWAP` | `0` | چرخه `swapoff/swapon` — روی سرور شلوغ خطرناک است (OOM killer)، خاموش بماند |
| `MAINT_JOURNAL_MAX` | `200M` | سقف حجم ژورنال (`--vacuum-size`) |
| `MAINT_JOURNAL_MAX_TIME` | `7d` | سقف عمر ژورنال (`--vacuum-time`) |
| `MAINT_EXCLUDE` | — | فایل‌های سطح اول `/var/log` که هرگز نباید دست بخورند، با کاما جدا شوند |

همه این تنظیمات از منوی 🧹 **Maintenance** هم قابل تغییر است (`vpssec maint`).

## سپر بات و اسکنر

از منوی **🛡️ Bot & Scanner Shield** (یا `vpssec shield enable`) فعال کنید:

- **محدودیت نرخ** — قوانین `limit` در ufw برای SSH و همه پورت‌های محافظت‌شده: بیش از **۶ اتصال جدید در ۳۰ ثانیه** از یک IP دراپ می‌شود (این کار اسکنرهای پورت و بات‌های حمله را از کار می‌اندازد). پورت‌های تانل مستثنا هستند — با `vpssec tunnels add` اعلامشان کنید.
- **ایمنی بن** — هرگز loopback، آدرس‌های خصوصی/CGNAT/link-local و همتاهای موجود در لیست *never block* (GeoIP bypass) بن نمی‌شوند؛ موارد نادیده‌گرفته‌شده در لاگ ثبت می‌شوند.
- **دراپ بسته‌های فلگ TCP** — اسکن‌های NULL، SYN+FIN، SYN+RST و ALL-flags در `before.rules` ufw دراپ می‌شوند (پس از ریبوت و reload پایدار می‌مانند)
- **تشخیص به‌جای بن خودکار** — IPهایی که پورت محافظت‌شده را با اتصال‌های نیمه‌باز (بیش از ۴۰ تا SYN-RECV) شلوغ می‌کنند، به‌عنوان **هشدار در انتظار تأیید** گزارش می‌شوند (`sudo vpssec alerts`) نه بن. با تأیید شما `ufw deny from <ip>` به مدت **۲۴ ساعت** اعمال می‌شود (`BAN_SECONDS` در `/etc/vps-security/botshield.conf`)؛ بن‌ها خودکار منقضی می‌شوند (تایمر نگهداری هر ۱۰ دقیقه) و فوری قابل لغو هستند. **پورت SSH همیشه در این اسکن هست** تا حملات brute-force به SSH هم دیده شوند — اما پورت‌های تانل اعلام‌شده هرگز محدود و هرگز گزارش نمی‌شوند
- مدیریت IPهای بن‌شده از همان منو: مشاهده لیست با زمان باقی‌مانده، یا بن‌زدنی فوری هر IP

## فیلتر جغرافیایی کشورها

از منوی **🌍 GeoIP country filter** (یا `vpssec geo ...`):

1. **➕ افزودن کشورهای مجاز** — هر تعداد کشور، با هر املایی که راحت هستید وارد کنید؛ **بیش از ۱۲۰ کشور** از قبل شناخته شده‌اند و تطبیق نام‌ها انعطاف‌پذیر است:
   - کد دوحرفی: `IR,DE,TR,US`
   - **نام کامل**: `Iran,Germany,Netherlands,Turkey`
   - **نام فارسی**: `ایران,آلمان,هلند,ترکیه`
   - کد سه‌حرفی ISO با هر بزرگی/کوچکی: `USA,IRN,deu`
   - **نام‌های جایگزین**: `holland`، `deutschland`، `england`، `dubai`، `america`، `korea`
   - شکل کوتاه و غلط تایپی ساده: `netherland`، `nederlands`، `germny`، `qater` هم تشخیص داده می‌شوند
   - ورودی ناشناخته یا **مبهم** هیچ تغییری ایجاد نمی‌کند و راهنما نشان می‌دهد: `'Turk' is not a valid country code or name … Did you mean: TR (turkey), TM (turkmenistan) ?`
   - کد را حفظ نیستید؟ گزینه **📖 Country codes & names** در منو (یا `vpssec geo names`) جدول کامل کد/نام/نام‌های جایگزین را چاپ می‌کند.
2. **✅ Enable filtering** — لیست CIDR هر کشور دانلود (پایگاه داده IPFire، به‌روزرسانی روزانه) و در یک **ipset** بارگذاری می‌شود و ufw طوری تنظیم می‌شود که *فقط* کشورهای انتخابی به سرور دسترسی داشته باشند — بقیه دراپ می‌شوند
3. **🛟 Bypass** — IP خودتان را اضافه کنید تا حتی از کشور مسدود هم هرگز بلاک نشود (منو، IP عمومی فعلی شما را نشان می‌دهد)
4. **♻️ Refresh** — لیست‌ها هر هفته خودکار به‌روز می‌شوند؛ هر زمان بخواهید می‌توانید دستی به‌روزرسانی کنید
5. **⛔ Disable** — همه قوانین فوراً حذف می‌شوند؛ دوباره همه کشورها می‌توانند متصل شوند

دستورات مستقیم: `vpssec geo add IR,DE` (کد، نام کامل یا نام فارسی) · `vpssec geo remove TR` · `vpssec geo names` (جدول راهنما) · `vpssec geo list` · `vpssec geo enable|disable` · `vpssec geo bypass <ip>` · `vpssec geo refresh`

> ⚠️ فیلتر جغرافیایی را **بعد از** اطمینان از سلامت اتصال SSH فعال کنید، و اگر از کشوری متصل می‌شوید که در لیست مجاز ندارید، حتماً IP خودتان را در Bypass اضافه کنید.

> 🛡️ **ایمنی داخلی — هرگز به‌صورت تصادفی کل جهان را بلاک نمی‌کنید:**
> - اگر **هیچ کشوری تنظیم نشده باشد**، فعال‌سازی فیلتر رد می‌شود و سرور از **همه جای جهان** قابل دسترسی می‌ماند.
> - اگر دانلود لیست همه کشورها **شکست بخورد**، قوانین مسدودسازی هرگز نصب نمی‌شوند.
> - **حذف آخرین کشور مجاز** در حین فعال بودن فیلتر، به‌طور خودکار فیلتر را غیرفعال می‌کند و سرور دوباره برای همه کشورها باز می‌شود.
> - **هنگام بوت**، تنظیمات ناامن (بدون کشور / لیست خالی / بدون bypass) هرگز قانون DROP جهانی را دوباره اعمال نمی‌کند.

## API محافظ (نقطه پایانی وضعیت محلی)

سرویس guard اختیاری، وضعیت مانیتور را روی `127.0.0.1:18080` ارائه می‌دهد:

```bash
curl http://127.0.0.1:18080/health   # {"status":"ok"}
curl http://127.0.0.1:18080/status   # پورت‌های مجاز، مسدود، هشدارهای در انتظار و رویدادها
```

مقدار `pending_alerts` تعداد رویدادهای تشخیص‌داده‌شده و **هنوز تأییدنشده** است — ممکن است بزرگ‌تر از صفر باشد در حالی که هیچ پورتی مسدود نیست.

به‌صورت پیش‌فرض فقط محلی است — بدون یک reverse proxy دارای احراز هویت آن را عمومی نکنید.

## نکات ایمنی

- تغییر پورت SSH از `sshd_config` **پشتیبان** می‌گیرد، با `sshd -t` اعتبارسنجی می‌کند و در صورت بالا نیامدن sshd روی پورت جدید، **خودکار به حالت قبل برمی‌گردد**.
- ufw **بعد از** مجاز شدن پورت‌های شما (از جمله SSH) فعال می‌شود، پس هرگز خودتان را قفل نمی‌کنید.
- **هیچ‌چیز بدون تأیید شما بن نمی‌شود.** مانیتور و سپر فقط هشدار ثبت می‌کنند؛ بن/مسدودسازی بعد از فشردن **y** در `vpssec alerts` اعمال می‌شود. پورت‌های مجاز، پورت‌های تانل، پورت SSH، آدرس‌های loopback/خصوصی و IPهای GeoIP bypass حتی در صف هم قرار نمی‌گیرند.
- **هر بن موقت و قابل لغو است.** بن‌های تأییدشده ۲۴ ساعت دوام دارند، با تایمرها خودکار منقضی می‌شوند و پیش از موعد هم با `vpssec unblock <port>` یا `vpssec shield unban <ip>` آزاد می‌شوند — اشتباه‌ها همیشه جبران‌پذیر می‌مانند.
- `vpssec uninstall` یک **بازنشانی کامل (factory reset)** انجام می‌دهد: تمام سرویس‌ها متوقف و حذف می‌شوند، همه فایل‌های تنظیمات و وضعیت پاک می‌شوند، پورت SSH به **۲۲** برمی‌گردد و `ufw reset` → `ufw allow 22` → `ufw disable` اجرا می‌شود؛ در نتیجه سرور دقیقاً مثل روز اول — باز و با SSH روی پورت ۲۲ — باقی می‌ماند.

## عیب‌یابی

- **منوی `vpssec` بالا نمی‌آید.** دستورهای `sudo vpssec --version` و `sudo vpssec help` را اجرا کنید؛ اگر خطایی مانند *libraries not found* دیدید نصب کامل نشده است — نصب‌کننده یک‌خطی را دوباره اجرا کنید.
- **از طریق SSH هیچ اتفاقی نمی‌افتد؟** CLI به ترمینال نیاز دارد. روی ورودی لوله‌ای (CI، `cron` یا برخی کنسول‌های وب) به‌طور خودکار به منوی شماره‌دار برمی‌گردد.
- **نصب خودکار و بدون دخالت.** متغیر `VPSSEC_NO_MENU=1` را تنظیم کنید تا `vpssec install` پس از پایان، منو را باز نکند.
- **منو را دوباره می‌خواهم.** هر دستور به شل برمی‌گردد؛ برای باز کردن دوباره منو کافی است `sudo vpssec` را اجرا کنید.
- **هشدارها زیاد شده‌اند؟** با `sudo vpssec alerts` بررسی کنید (**n** رد می‌کند، **a** همه را تأیید می‌کند) یا پورتی که سرویس شناخته‌شده‌ای روی آن کار می‌کند را برای همیشه ساکت کنید: `sudo vpssec ports` (مجاز) یا `sudo vpssec tunnels add <port>`. برای بازگشت به حالت کاملاً خودکار، `MONITOR_MODE=auto` و `SHIELD_MODE=auto` را تنظیم کنید.
- **هشدار هست ولی در ورود SSH چیزی دیده نمی‌شود؟** فایل هشدار ورود `/etc/update-motd.d/99-vps-security-alerts` است و فقط وقتی صف خالی نباشد چیزی چاپ می‌کند؛ اگر مسیر state را جابه‌جا کرده‌اید `VPSSEC_STATE_DIR` را تنظیم کنید.

## تست‌ها

هیچ‌کدام از تست‌ها به سرور واقعی دست نمی‌زنند: دستورهای `ufw`، `ss`، `systemctl`، `apt-get`، `ipset` و `curl` با استاب (stub) شبیه‌سازی می‌شوند و همه مسیرها به یک سندباکس موقت هدایت می‌شوند.

```bash
bash test/smoke.sh              # ۲۹۸ چک: نصب کامل، تشخیص و تأیید هشدار، انقضای بن، سپر، GeoIP، نگهداری، میرور گیتهاب / DNS / میرور apt (همراه با rollback)، CLI از مسیر symlink، فریم‌های TUI، حذف کامل
                                # (روی سرور لینوکسی چک‌های منو روی pty، تأیید تعاملی y/n و API زنده هم اضافه می‌شوند)
bash test/simulate-two-host.sh  # ۷۶ چک: دو سرور شبیه‌سازی‌شده (ایران + خارج) با پنل 3x-ui و تانل backpack
```

شبیه‌سازی دو‌سروره همان استقرار واقعی شما را می‌سازد — سرور خارجی با پنل 3x-ui/سنایی (پورت `2087` API و `2096` اشتراک) و **سرور تانل backpack** روی `8443`، و سرور ایران با **کلاینت** تانل روی `443` که به خارج وصل می‌شود و از `127.0.0.1:2087` به پنل می‌رسد. vpssec روی **هر دو** سرور نصب می‌شود و ثابت می‌کند امنیت هیچ‌وقت تانل را نمی‌شکند: پورت‌های تانل و پنل باز می‌مانند و هرگز بلاک/محدود نمی‌شوند، سوکت‌های خروجی تانل و فورواردهای loopback نادیده گرفته می‌شوند، **پورت‌های غریبه واقعی هنوز تشخیص داده و پس از تأیید بلاک می‌شوند**، GeoIP فقط اتصال‌های NEW را دراپ می‌کند، نصب مجدد قوانین تانل را حفظ می‌کند و uninstall روی ایران، سرور خارجی را دست‌نخورده می‌گذارد.

هر دو مجموعه در **GitHub Actions** و روی هر push خودکار اجرا می‌شوند (`.github/workflows/deploy-smoke-test.yml`).
